# 后台提醒真机排查

日期：2026-09-22。用户反馈从最近任务列表划掉「此刻」后收不到提醒。

## 环境与原因

本次通过 USB ADB 检查用户手机：vivo V2454A，Android 16 / API 36，系统属性 `ro.vivo.os.version=16.0`，构建版本 `PD2454B_A_16.1.20.6.W10`。手机安装的是 `0.2.0-mvp-dev`（versionCode 2），本次使用该已安装版本完成验证。

发现的系统状态：

- 系统通知权限已开启。
- 自启动未开启，后台耗电管理为「智能控制后台耗电」。
- 初始应用处于 `stopped=true / vStopped=true`，没有有效的未来提醒。
- 系统闹钟历史中，多次记录此刻的提醒因 `Reason=frozen` 被移除；应用离开前台后的本次对照也出现了相同记录。
- 重新打开应用能重新登记提醒，但初始为非精确闹钟，`windowLength=3600000`，即系统登记了一小时的投递窗口。

这些结果把本次故障定位在手机系统对应用的后台冻结和启动限制。应用已经使用 `AlarmManager` 和清单注册的 `BroadcastReceiver`，实际提醒不依赖页面持续打开。

## 本机设置

1. 在系统设置的「自启动」中找到「此刻」，开启开关。该机界面标注此开关管理「开机启动、后台启动」。
2. 在「此刻」应用信息 → 电量 → 后台耗电管理，选择「允许后台耗电」。
3. 重新打开「此刻」，恢复系统提醒安排。
4. 检查「闹钟与提醒」以及应用编辑页的准时提醒状态。

本次改变的是自启动和后台耗电策略。设置后 `dumpsys deviceidle whitelist` 出现此刻，闹钟变为 `windowLength=0 / exactAllowReason=allow-listed`：这台手机通过允许名单获得了精确提醒能力。不能把这个状态误写成单独授予了 `SCHEDULE_EXACT_ALARM`；若以后撤销后台耗电允许，需重新检查准时提醒权限。

## 实测结果

通过应用表单创建独立临时项目 `NowlyReminderProbeTest23`，设置当天 16:34 的提醒，然后从最近任务划掉此刻并锁屏。

| 时间（北京时间） | 实际观察 |
| --- | --- |
| 16:32:47 | 系统登记 16:34:00 的精确提醒，投递窗口为 0 |
| 16:33:56 | 已划掉应用并锁屏；`pidof` 查不到此刻进程，提醒仍存在，`stopped=false / vStopped=false` |
| 16:34:01.121 | 系统通知记录的创建时间，距计划时间约 1.1 秒；通知未被拦截 |
| 16:34:17 | 检查到此刻由系统重新启动的进程，以及自动登记的下一次 17:00 提醒 |

这次验证覆盖了真实手机上「从最近任务划掉 → 进程退出 → 锁屏 → 系统启动应用并发出通知」的完整链路。没有修改业务代码或覆盖安装 APK。

验证范围为本机这一次近时刻提醒；跨夜、深度休眠、整机重启及其他厂商手机仍需分别验证。
