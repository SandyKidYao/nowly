# 此刻 · Nowly：首版初始需求

> 本文用于创建项目、项目初始化和后续规格设计。它记录已确认的产品意图与范围，不是技术方案或完整行为规格。「待规格设计明确」中的内容尚未确定，不应当作已获确认的实现要求。

## 1. 产品定位与目标

此刻（Nowly）是一款轻量的日常状态采样记录 App。用户创建自己的记录项目，设置采样提醒，在提醒到来时用尽可能少的操作记录当下状态，再通过统计了解自己的日常变化与规律。

首版支持 Android，首先供发起人本人使用。首个实际使用场景是观察自己的日常心理压力，但产品从首版起就支持自定义记录项目，不限定为压力或心情专用工具。

产品体验的重点是减少操作和打扰：记录应当简短、直接；用户不方便回应时，可以自然地错过，不产生补填负担。

## 2. 已确认的首版范围

| 维度 | 已确认要求 |
| --- | --- |

| 组织方式 | 以「记录项目」组织记录，用户可以自行创建和设置项目 |

## 3. 记录项目

「记录项目」是用户配置和使用采样的基本单位。

每个项目需要能够表达以下产品信息，具体界面和数据结构留待规格与方案设计：

- 项目名称，例如「心情」「心理压力」。
- 一个采样问题，例如「此刻，你感到多大压力？」。
- 一组由用户设置的单选选项。
- 该项目每日的具体提醒时间点，次数由时间点数量决定。
- 该项目下的记录及统计结果。

用户可以创建、设置不同项目。首版一个项目只问一个问题，不在一次记录中连续询问多个问题。

预置项目和新建项目的提醒开关默认开启。首页每个项目卡片右上角放置独立开关，关闭后暂停该项目的后续提醒，保留项目配置和历史记录；开关操作不跳转页面。点击项目标题直接进入该项目详情，不另设“查看项目”区域。首页不显示右上角“提醒未开启 / 提醒已开启”标签，也不放置单独的“开启提醒”按钮。

创建项目采用一张可上下滚动的表单，从上到下填写项目名称与问题、回答选项、采样提醒；不使用“下一步 / 上一步”切换页面。编辑复用这张表单，提醒时间轴及时间点的增删调整也在页内完成，底部保留一个保存入口。

### 标签 ID 与历史展示

- 每个回答选项（标签）有独立且稳定的 `optionId`；ID 不由名称或列表位置决定，改名不生成新 ID。
- 回答记录引用 `optionId`，展示名称从该选项的当前名称读取。修改名称后，历史列表、回答选项和三类统计同步显示新名称，不需要逐条改写历史记录。
- 改名不改变历史记录的填写时间、提醒时间、所选 ID 或统计次数；统计按 ID 分组，不能按名称字符串分组。
- 新增选项分配新 ID；即便名称与另一个选项相同，也不自动复用 ID 或合并历史。
- 已被历史记录引用的 ID 必须保持可解析。选项移出后续可选列表时，不得让历史引用失效；具体停用/删除展示细节留待规格设计。
- 移除 D07“修改内容影响”确认页。采用上述默认规则，编辑保存后直接回到项目详情，不因标签改名拆分历史版本或增加确认步骤。

项目详情的设置入口直接进入编辑表单，不再经过独立项目设置页。编辑页滚动到最底部可以删除当前项目；新建项目时不显示删除入口。删除后的历史数据处理等具体语义仍待规格确定。

项目详情以今天的采样记录为首，按日期分组向下延伸，滚动时自动加载更早历史，直到没有更多记录。不再展示提醒已开启、提醒时间和修改提醒安排的配置方框。记录在详情列表内阅读，不再提供独立记录列表页或单条记录详情页；尚待回答的提醒仍可进入作答流程。

### 初始项目与首个使用场景

- **预置项目：心情。** 具体问题文案、默认选项及初始提醒配置尚待规格设计。
- 首次打开直接显示项目首页中的预置心情项目，提醒开关默认开启；用户点击标题进入详情，并在项目内调整问题、选项和提醒。
- 项目提醒开关与 Android 系统通知授权分别管理；默认开启不等于已经获得系统权限。首次需要授权时通过系统弹窗申请，具体触发时机留待规格确定，不设置独立权限引导页。
- **发起人的使用项目：心理压力。** 已讨论的选项示例为「无、轻微、中等、较高、很高」，用于快速选择当下的主观压力程度。这组示例不应成为所有项目固定使用的选项。

## 4. 采样提醒

采样提醒是项目的一项可配置功能。用户为每个项目设置一组每天重复的具体时间点，可以使用不等间隔的安排；例如 10:00、12:00、15:00、17:00、20:00。

### 手动时间轴

- 时间轴呈现一天中的提醒分布。
- 初始提供一组可编辑时间点；原型以 5 个点和上述时刻演示，最终默认时刻仍可调整。
- 用户可以逐个调整具体提醒时间，也可以添加或删除时间点。
- 显示的每日提醒次数随时间点数量自动变化，不再单独填写次数。
- 首版只保留手动配置，不再提供严格等间隔、随机偏移或“次数 + 生效范围”自动生成提醒的模式。

原型提供拖动圆点粗调和时间输入精确修改；拖动步长、时间点数量限制、重复时间与同日修改生效规则留待规格设计明确。

### 与旧方案的关系

本节替代旧版“次数、时间范围、两种自动采样模式”的配置方式。原先 08:00–20:00 的示例不再构成时间轴的限制；用户按具体时刻表达自己的日程。

## 5. 一次记录的体验

目标流程为：

**收到提醒 → 点击通知进入回答页 → 选择一个答案 → 保存成功后直接返回。**

- 尽量减少从提醒到完成记录的操作步骤。
- 选择答案后直接保存，不额外要求点击提交或确认。
- 保存成功后直接返回进入前的界面，不跳转到保存成功页，不需要再点一次返回。通知入口返回此前界面；App 内入口返回原页面。
- 保存应可靠完成；保存失败视为实现缺陷，不设计独立失败页或正常流程中的失败分支。具体可靠性与异常诊断由实现和测试解决，不得将未保存当作成功。
- 首版每次只回答该项目的一个问题。
- 不设置“提醒发出若干分钟后自动过期”的逻辑。回答的是填写时的当下状态，以实际选择答案的时间戳记录，而非追填提醒发出时的状态。例如 09:00 提醒、10:00 作答，记录与统计归到 10:00。
- 同一项目只保留最新一条待处理通知；新提醒到来时替换尚未处理的旧通知，旧提醒标为「未处理」，不算用户主动跳过，也不要求补填。
- 点击通知上的「跳过」或划掉通知，结束该次提醒并记为「已跳过」，不打开回答页、不产生答案。系统「全部清除」清除对应通知同样算跳过。
- 没有回答、没有主动跳过、也没有被后续提醒替换时，保持「待处理」；不能仅因时间流逝就改成已跳过或未处理。
- 「已回答」「已跳过」「未处理」是不同结果；「待处理」表示尚未结束。「已跳过」与「未处理」均不能记成「无压力」或其他选项。

首版采用点击通知进入回答页的交互，通知另外提供「跳过」按钮；本轮不采用在通知中排列全部自定义答案的方案。替换、作答、划掉同时发生，以及用户已进入回答页时收到下一次提醒等边界，仍需在规格设计中明确。

## 6. 统计与本地保存

统计从项目详情进入，始终限定当前项目。日期趋势、时段分布和按选项统计在同一页纵向排列，可上下滚动。筛选只提供日期范围，不再选择项目。统计页不提供查看记录入口，历史记录统一在项目详情中浏览。

### 日期趋势

帮助用户观察记录随日期的变化，例如自己的压力在最近几天、几周是否呈现不同分布。

已回答记录按实际填写时间所属日期归组，不按原定提醒日期归组。

### 时段分布

帮助用户观察一天中不同时段的差异，例如哪些时段更容易记录到较高压力。

已回答记录按实际填写时间所属时段归组；提醒计划时间不能替代记录时间。已跳过、未处理没有答案，不混入回答分布。

### 按选项统计

在所选日期范围内，按各答案选项汇总回答次数与占比，便于看清哪些选项出现得多。占比以已回答记录为分母，已跳过和未处理不作为答案计入；普通分类与有序等级都可使用。

选项分组键为稳定 ID，名称仅作显示；改名后仍是同一组历史数据，次数、占比和时间分布保持不变。

### 本地保存

- 记录仅保存在本机，首版无需账号或登录。
- 回答自动保存在手机本地，无需额外执行保存或管理文件的操作。
- 首版移除本地数据管理、导出配置、系统文件保存等专门界面；不提供独立的全局设置页，项目自己的问题、选项和提醒设置保留。
- 导出功能移出首版 MVP，后续需要时再确定格式、字段和范围；数据导入恢复也不属于首版。

统计公式、图表类型和时间范围选择方式留待规格设计。由于选项可自定义，不能直接假定所有项目的选项都有数值大小关系；普通分类与有序等级应如何呈现，是后续需要解决的设计问题。

## 7. 首版边界

以下不属于本次已经确认的首版交付范围。若要加入，需要单独讨论其必要性与成本：

- iOS、微信小程序及其他平台。
- 账号、云同步、跨设备使用。
- 多人参与、研究者管理和统一发放采样项目。
- 一个项目包含多道问题或连续问卷。
- 数值输入、自由文本、多选等其他答案类型。
- 心率或其他健康数据的自动读取、设备接入。
- 纯随机采样、主动延后提醒、回填过去时刻的状态。
- 按次数与范围自动生成等间隔提醒、随机偏移提醒等自动安排模式。
- 数据导入恢复、自动分析结论等未确认的扩展功能。
- 首次欢迎/引导流程、独立的本地数据管理界面和文件导出功能。

心率等身体指标曾作为产品未来可拓展用途讨论，但首版已确定采用自定义单选，不应据此直接加入数值记录或健康设备集成。

## 8. 意图层面的完成标准

以下用于指导后续规格拆解，具体测试方法与量化指标仍需在规格、方案阶段确定：

1. 用户首次打开直接看到预置心情项目，项目提醒默认开启，可在卡片右上角切换，点击标题进入详情；也能在同一张滚动表单中创建其他项目并一次保存。
2. 每个项目可独立设置每日提醒时间点；时间轴支持调整、增加、删除，显示次数与时间点数量一致；首版不提供自动采样模式。
3. 用户能从提醒进入记录流程，选定答案后按填写时间保存，成功后直接返回，无单独保存成功页。
4. 通知不按时长自动过期；同项目新提醒替换旧提醒后，旧的标为未处理。主动点击跳过或清除通知记为已跳过；这些状态都不产生答案，不触发补填要求。
5. 用户从项目详情进入统计，在同一张滚动页面查看日期趋势、时段分布和按选项统计，并仅按日期筛选；统计应与实际保存的数据保持一致。
6. 核心使用流程无需登录，记录保存在本机。
7. 项目详情直接显示当天记录，并在向下滚动时加载历史；不设独立记录列表或记录详情页。设置直达编辑页，删除入口位于编辑页底部。
8. 修改已使用选项的名称后，历史记录与统计显示新名称，但选项 ID、历史时间及统计数量均保持不变；保存无需经过修改影响确认页。

这些问题不会改变已确认的产品定位，但在实现前需要确定具体行为。

| 标签边界 | 稳定 ID、改名同步历史与按 ID 统计已确定；同名选项的界面限制、停用选项的展示及问题/选项类型变更的行为仍待明确 |
| 初始体验 | 已确定首次直接进入项目首页、无引导流程；预置心情项目的具体内容、初始时间点数量与默认时刻仍待明确 |

| 时间设置 | 按星期设置是否必要；时间、时区和夏令时变化后的处理 |

| 记录入口 | 已确定点击通知进入回答、保存后直接返回，无保存成功页或保存失败页；选项较多时的展示，误触、重复操作及未作答返回的行为仍待明确 |
| 提醒状态边界 | 已确定不按时长过期、替换旧提醒记未处理、主动清除记已跳过；新提醒到来时旧回答页已打开、保存与跳过并发、系统或 App 自行移除通知时如何处理仍待明确 |
| 统计口径 | 已回答按实际填写时间归组；分类与等级的展示、具体日期/时段边界、已跳过和未处理的数量归属、是否展示回应率及其分母仍待明确 |
| 历史列表 | 项目详情无限滚动加载历史已确定；每批数量、同日记录排序、跨日归属与没有记录时的呈现仍待明确 |
| 本地数据 | 本地保存的可靠性、项目删除与历史记录的关系；导出、备份恢复不在首版范围 |

### v7 · 2026-09-17：围绕项目合并页面

- 移除 App 底部导航，统计改从项目详情进入。

- 移除统计页的记录查看入口，以及独立记录列表和记录详情页面。

### v6 · 2026-09-17：简化首页项目卡片

- 项目提醒默认开启，包括预置心情项目和新建项目。
- 首页卡片右上角用滑块开关替代开启状态标签，移除卡片中间的“开启提醒”按钮。
- 删除独立的“查看项目”区域，改为点击项目标题进入详情。
- 首页开关与项目内的提醒开关控制同一状态；系统通知权限仍需通过 Android 授权。

### v5 · 2026-09-17：改用手动提醒时间轴

- 用户选择首版只保留手动时间点，移除等间隔和小幅随机模式。
- 时间轴支持调整具体时刻、添加与删除时间点；每日次数等于当前时间点数量。
- 使用 10:00、12:00、15:00、17:00、20:00 五个时间点作为原型初始示例。
- 配置仍在 D01 单页表单内，其他记录、跳过与旧通知替换规则不变。

### v4 · 2026-09-17：合并项目创建页面

- 将原型中的问题、选项、提醒三步合并为同一张可上下滚动的表单，取消“下一步 / 上一步”。
- 时间范围直接在表单中设置，不额外设计独立的时间范围页面；系统时间选择器可以正常使用。
- 创建与编辑复用表单，底部提供一个保存入口。

### v3 · 2026-09-17：缩减 MVP 界面范围

- 移除首次欢迎、预置项目确认和独立通知权限引导，首次直接进入项目首页。
- 保留预置心情项目与本地自动保存；启用提醒时再请求系统通知权限。
- 移除独立全局设置和本地数据管理界面；导出功能推迟到后续版本。项目内的问题、选项、提醒设置保留。
- 对“去掉本地数据相关”的落实范围为去掉相关功能界面，记录仍保存在本地。

### v2 · 2026-09-17：简化提醒与完成流程

- 移除 v1 中“提醒超时后自动过期并标为未回应”的要求，改为同项目只保留最新待处理通知，旧通知被替换后标为未处理。
- 新增主动跳过：点击通知上的跳过按钮或清除通知，记为已跳过。
- 回答记录填写当下，以实际填写时间归入日期和时段统计。
- 保存成功后直接返回，取消单独的保存成功页。
- 保存失败视为实现缺陷，不为其设计产品界面。
- 本变更来自原型评审中的用户确认；其他未确认的线框设计继续保持拟议状态。

## 附：关键原始表述

> 产品应该足够简洁，每次统计尽量减少操作的步骤，让用户无感。

> 不一定要统计心情啦，其实可以做很多其他的类似统计工作，帮助人们监控自己的日常状态，比如提醒自己看下心率、抽样自己日常在做什么事之类的

> 记录本身是一个类似“项目”一样的东西，用户可以自己创建、设置一个记录，比如默认的我们可以用记录心情这个作为一个初始项目，也就是你说的通用自定义问题

> 次数也允许用户设置，生效的时间范围也允许用户设置，并且不是纯随机采样，而是有两种模式让用户可以选，第一种是完全等等间隔采样，每次采样之间间隔相等，第二是在这个相等的间隔基础上，稍微加一点随机元素，在这个时间或早或晚一点的时候给用户发送提醒。
