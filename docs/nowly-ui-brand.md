# 此刻 · Nowly：首版 UI 与品牌基线

用户已选择 **A · 苔灰**，并确认圆环与实心点的图标方向。首版以简洁、自然、安静为基调，页面结构和业务规则继续遵循定稿线框与需求文档。

本基线确定浅色外观、主要配色、字形方向、组件形态和图标构图。尺寸为当前预览的实现参照，实际系统字体、字体缩放和 Android 图标资源在实现时核对。

## 2. 品牌表达

- **名称**：此刻 · Nowly。首页的英文微标识可使用 `NOWLY`。
- **气质**：自然、安静、轻盈；保持日常工具的清楚与直接。
- **品牌短句**：留意此刻，就够了。用于品牌介绍，不增加欢迎或引导页面。
- **图形**：有留白的圆环与中央实心点。沿用已选图形的比例，不拉伸，不增加钟表指针或情绪表情。
- **用色**：默认深苔灰标志配浅苔灰底；页面中以小尺寸使用，主要空间留给内容。
- **文字语气**：短句、具体、平和。围绕“记录当下”“查看统计”等动作，不给感受贴好坏标签。

应用图标 SVG 是视觉构图源文件。平台需要的自适应图标、单色通知图标和不同尺寸资源，应在 Android 工程初始化时从该图形派生并实机检查。

## 3. 配色

| 角色 | 色值 | 使用位置 |
| --- | --- | --- |
| 页面底色 | `#F3F4EF` | 页面背景、顶部栏和操作区背景 |
| 内容表面 | `#FCFCF9` | 项目卡片、输入框、回答选项、底部面板 |
| 主色 | `#526B5B` | 主要按钮、开启的开关、时间轴选中点、重要数字 |
| 主按钮文字 | `#FFFFFF` | 深苔灰按钮上的文字 |
| 主要文字 | `#29362F` | 标题、问题、答案和主要内容 |
| 辅助文字 | `#58665D` | 时间、说明、次要状态和图例 |
| 浅色容器 | `#E5EAE1` | 选中状态、轻量标签、图标背景 |
| 边框与分隔 | `#D9E0D5` | 卡片边框、输入边框、列表分隔 |
| 少量暖色点缀 | `#C6B7A1` | 少量中性状态点缀，例如待处理标签的浅底色 |

大面积使用浅色背景，主色集中在操作与重点信息上。首版使用这套固定品牌配色，平台默认色或动态取色不自动覆盖此基线。默认组合的计算对比度：正文/底色 **11.42:1**，辅助文字/底色 **5.47:1**，白字/主按钮 **5.81:1**；完整组件状态仍需在实现时检查。

图表使用同色系明度层次：`#DCE3D8`、`#BCCAB8`、`#99AD95`、`#728D70`、`#496548`。同时显示名称、次数、占比或图例；不只依赖颜色区分。选项改名应保持其统计身份与对应颜色一致。

## 4. 字体与尺度

使用设备系统无衬线字体，不依赖联网字体。中文预览采用系统字体回退；正文与数字保持统一的字形气质。

| 层级 | 预览字号 | 字重方向 |
| --- | --- | --- |
| 首页“此刻” | 29 | 较醒目，约 600 |
| 回答页问题 | 27 | 中等字重，行高约 1.55 |
| 项目标题 | 17 | 中等字重 |
| 页面栏标题 | 15 | 中等字重 |
| 回答选项 | 15 | 常规 |
| 主要正文 | 14 | 常规 |
| 控件文字 | 13 | 常规 |
| 辅助说明 | 11 | 常规、保持足够对比 |
| 统计重点数字 | 28 | 中等字重 |

标题按完整短语换行，避免把“心情”“压力”等词拆开。原生实现应把字号、字重映射到对应平台能力，适配系统字体缩放；不将预览中的行数和截断作为业务限制。

## 5. 组件形态

| 组件 | 基线 |
| --- | --- |
| 项目卡片 | 约 16–17 的圆角，浅表面色，细边框，不依赖重阴影 |
| 普通按钮与输入框 | 12 的圆角；主要按钮为深苔灰底与白字 |
| 回答选项 | 14 的圆角，至少 52 的高度；各答案保持相同视觉权重 |
| 底部面板 | 顶部圆角约 24，轻分隔，保持内容紧凑 |
| 选项标签 | 7 的圆角，浅容器色与深文字 |
| 状态标签 | 5 的圆角，克制的小色块 |
| 主要操作 | 至少 48 的高度；小图标在原生实现中扩展触控范围 |
| 内容留白 | 页面水平边距约 20，卡片内部约 15–16；区块间留出明确间距 |

预览中的设计尺寸可在 `nowly-design-tokens.json` 中查阅。Android 落地时映射为相应的布局与文字单位，并结合真实屏幕、字体缩放核对。

## 6. 五个核心页面

| 页面 | 视觉重点与既定交互 |
| --- | --- |
| 首页 | 项目卡片、标题入口、右上角提醒开关。提醒默认开启；当前待处理记录的主要操作更醒目。 |
| 项目详情 | 以日期和记录构成清楚的纵向节奏；滚动加载历史，统计入口容易找到，设置直达编辑。 |
| 回答 | 大问题、等权重选项、足够点击面积。点选即保存并返回，不加提交或保存成功页。 |
| 创建/编辑 | 分区清晰的一页滚动表单；手动时间轴可操作；保存入口稳定，编辑时删除位于表单底部。 |
| 统计 | 日期、时段、选项三类统计同页。弱化装饰，突出数据与图例，筛选仅针对日期。 |

界面不新增底部导航、首次引导、账号或导出入口。通知区域遵循平台容器，品牌元素保持简洁，不能把 HTML 通知示意当成所有机型的精确外观。

## 7. 实现交接

- A 的主要色值、图标构图和整体气质作为首版基线；三方案对比页保留作设计过程记录。
- UI 预览沿用定稿线框的页面与操作脚本，属于交互演示，不代表 Android 应用已经实现。
- 图标 SVG、设计变量和独立 UI 预览可直接交给后续实现使用；技术选型及工程状态见[技术选型文档](nowly-technical-selection.md)与[项目 README](../README.md)。
- 系统字体、完整触控/焦点状态、图标平台打包与真机显示在实现时核对。深色外观不在本次已确认的浅色基线中。
- 默认时间点、删除的数据语义、权限时机等业务待定项继续以需求文档为准，不由视觉设计隐式决定。

## 8. 选项排序交互更新 · 2026-09-18

- 用户确认改用左侧六点手柄拖动排序，中间保持文字输入，右侧保持删除。
- 移除独占一行的“上移”按钮；拖动时整行轻微浮起，其他行让位，开始/结束提供轻触反馈。
- 表单保持一个滚动区域，选项在其所属区段内调整；屏幕阅读器可使用“上移/下移”动作。
- 修改保存在草稿里，点击“保存项目”统一保存。实现与验收见 [选项拖动排序](option-reordering.md)。
